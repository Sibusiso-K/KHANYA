## How REEFPRINT should sit with existing tools

REEFPRINT should complement specialist tools and connect sample identity, imagery, sensor data, model evidence and reviewable process advice. It should not replace geological capture or claim to replace a full implicit geology model.

| Tool | Strong role | REEFPRINT relationship |
|---|---|---|
| FieldMove Clino | Smartphone compass-clinometer, structural measurements, GPS-tagged notes/photos, offline basemaps and field observations. It can export CSV/MOVE/KMZ. | Keep it as a field capture tool when the team already uses it. Import exports by sample/location ID; don't rebuild its compass/stereonet functions. A phone photo is contextual metadata, not automatically an input to the polished-section model. |
| QGIS | Free, open-source desktop GIS for coordinate systems, maps, spatial data inspection, layers and layouts. QField is the mobile companion; QFieldSync/QFieldCloud support offline projects and synchronization. | Use QGIS for free GIS setup, quality checks and map exports. Optionally use QField instead of Clino only when the workflow is mostly custom forms, points, photos and editable map layers. Choose one authoritative field-capture route to avoid duplicate sample records. |
| Leapfrog Geo | Commercial desktop 3D implicit geological modelling for drillholes, surfaces, sections and block-model interpretation; imports drillhole tables and exchanges supported GIS/model formats. | Treat it as the expert geological model authoring system. Exchange sample/interval tables and spatial outputs through CSV/GeoPackage/OMF where supported; do not promise a proprietary live integration for the hackathon. |
| REEFPRINT | Browser-based sample-to-evidence workflow: register sample, attach high-resolution ore imagery, ingest field XRF and coordinates, run phase segmentation, report confidence/accuracy, show advisory and simulator response. | Build the missing workflow and traceability layer. Initially display sparse spatial observations in 2D/3D; don't interpolate them into a geological volume without adequate samples and validation. |

### Recommended product form

Build one responsive web application with a phone-friendly, offline-capable capture surface and a desktop-first analysis/review surface. A progressive web app (PWA) is a practical first form: installable from the browser, one codebase and centrally updated. On the phone, queue records, coordinates, notes, photographs and XRF readings locally, then synchronize when connectivity returns. At a workstation, inspect full-resolution imagery, overlays, per-class accuracy and the 3D spatial context. If a site's network or data rules require it, the same service can later run on a local server/edge machine; that deployment is a pilot decision, not an MVP prerequisite.

Do not assume an XRF Bluetooth protocol before selecting a device. The first MVP should accept a validated CSV or manual reading with instrument model, units, time, operator, sample ID and calibration/QC context. Add direct BLE/USB integration only after confirming the exact instrument and vendor protocol.

Keep image types explicit. The current model was trained on high-resolution labelled LumenStone S2 polished-section imagery. It must not silently classify ordinary phone photos or unvalidated hyperspectral/XRF inputs. Use FieldMove photos to locate and document the sample; use the matching laboratory/imaging workflow to create the AI input. Join them with a stable sample ID, hole/depth (where relevant), timestamp and coordinate reference system.

For the hackathon, use QGIS rather than building a GIS stack from scratch: prepare a small, clearly labelled map and export clean coordinates/sample tables for REEFPRINT. A web map can display those observations, while a modest 3D view shows the surface, hole traces and coloured sample intervals. Keep actual assays, XRF element values, model-predicted phase pixels, uncertainty and simulated actions in separate layers and legends. Leapfrog integration can remain export-first until a real project and licence are available.

### What can and cannot be claimed about speed

REEFPRINT's potential advantage is reducing the gap between obtaining an image/sensor reading and seeing a documented screening result plus a human-reviewed scenario. It is not established to be faster or better than FieldMove, QGIS, Leapfrog, SEM or XRD at their core tasks. The baseline run is a model-accuracy result, not an end-to-end latency benchmark. Before making a speed claim, measure capture-to-overlay time, upload/sync time in weak connectivity, workstation/edge inference time and a realistic lab comparison. Before changing real plant parameters, validate recommendations against site process data and use plant-engineer-approved safety limits.
